# 별도 교통·항공편 개발 연결 준비

2026-11-18. Google Routes/Places는 기존 개발 키를 유지한다. 아래 두 서비스의 계정/키는 아직 제공되지 않았으며 실제 연결 완료로 표시하지 않는다. 가입·과금·운영 전환은 앱 구현과 별개의 사용자 계정 작업이다. 비밀 키는 채팅/GitHub/앱 번들에 넣지 않는다.

## 먼저: 일본 전철·버스 시간

1. NAVITIME의 공식 [API 마켓 안내](https://api-sdk.navitime.co.jp/api/market/)를 연다.
2. 안내 안의 RapidAPI 링크를 연다. 공식 연결은 [NAVITIME 검색](https://rapidapi.com/search?term=NAVITIME&sortBy=ByRelevance)으로 이어진다.
3. RapidAPI 개발 계정을 만들거나 로그인한다.
4. 공급자가 NAVITIME JAPAN인 일본 경로 API를 확인한다. 역 사이 환승만이 아니라 주소/좌표 간 도보+대중교통을 다루는 경로 기능이 필요하다. 상품/권한을 정하기 전에 해당 화면을 함께 확인한다.
5. 무료 개발 플랜이 표시되면 호출 한도와 초과 요금/자동 결제 조건을 직접 확인한다. 무료 플랜이 없거나 결제를 요구하면 여기서 멈추고 상품 화면만 공유한다. 유료 플랜을 먼저 가입하지 않는다.
6. 키는 복사해 채팅에 보내지 않는다. 계정과 사용할 API 상품이 확인되면 맥북의 비공개 설정에 저장하고 실제 도쿄 구간으로 검증한다.

NAVITIME 공식 [API 소개](https://api-sdk.navitime.co.jp/api/)는 공공교통+도보의 두 지점 간 경로 기능과 직접 계약/마켓 계약을 안내한다. 이 페이지의 무료 플랜 표시는 모든 상품/계정에 자동으로 적용된다고 가정하지 않는다. 기존 Google Maps 앱에서 경로를 볼 수 있는 것과 앱이 교통시간 API 데이터를 사용할 권한은 다르다.

## 항공편: 개발 검증용 계정 후보

Amadeus Self-Service는 항공 검색을 검증할 후보이며 아직 Afield의 확정 운영 공급자가 아니다. 한국 항공사·저비용항공사·예약한 편의 실제 데이터 범위가 요구에 맞는지 확인해야 한다.

1. [Amadeus 개발자 회원가입](https://developers.amadeus.com/register)을 열고 개발 계정을 만든다.
2. 이메일 인증 후 [My Apps](https://developers.amadeus.com/my-apps)에서 개발용 애플리케이션을 만든다. 이름 예: Afield Development.
3. 테스트용 API Key / API Secret이 보이면 계정 준비가 된 상태다. 두 값은 채팅에 보내지 않는다.
4. 먼저 테스트 환경에서 출발/도착 공항·날짜·항공사/시간으로 검색 가능한 응답 구조와 데이터 범위를 검증한다. 테스트 응답을 사용자의 실제 항공편 확인 결과로 표시하지 않는다.
5. 실제 항공편 조회가 필요하면 Production 접근 조건·항공사 범위·비용을 별도로 확인한 뒤 결정한다. 테스트 계정을 만든 것만으로 실제 운항 정보가 연결됐다고 보지 않는다.

계정/앱 생성 경로는 Amadeus 공식 [Node SDK 안내](https://github.com/amadeus4dev/amadeus-node#readme)에서 확인했다. 연결 검증 전까지 Afield의 공항 검색/예약 내역 직접 입력은 계속 사용할 수 있다.

## 연결 완료 판정

키가 저장됐다는 표시만으로 완료하지 않는다. 실제 API 응답 → 출발/도착/수단/날짜/시각 변환 → 앱 표시 → 선택 적용을 확인한다. 교통시간 미확인이나 테스트 항공편을 실제 값으로 만들지 않는다. 현재 남은 외부 의존성은 두 계정의 실제 사용 권한과 검증 가능한 키다.
