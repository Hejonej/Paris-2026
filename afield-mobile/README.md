# Afield Mobile · 기존 기능 복원

React Native + Expo SDK 54 모바일 앱입니다. 변경은 `afield-mobile/`와 개발 브랜치 `feature/afield-mobile-shell`에만 적용합니다. 운영 main, Cloudflare 배포 설정, 웹 여행 데이터는 변경하지 않습니다.

## 맥북 ZIP 갱신과 Expo Go 실행

1. 실행 중인 Expo 터미널에서 **control + C**를 눌러 종료합니다.
2. [최신 개발 브랜치 ZIP](https://github.com/Hejonej/Paris-2026/archive/refs/heads/feature/afield-mobile-shell.zip)을 새 폴더에 풉니다. 이전 폴더와 섞지 않습니다.
3. 터미널에서 `cd `를 입력한 뒤 **새 폴더 안의 afield-mobile 폴더**를 끌어다 놓고 엔터를 누릅니다. 저장소 바깥 폴더에서 실행하면 안 됩니다.
4. 아래 명령을 하나씩 실행합니다. 이번 버전은 파일 선택 모듈이 추가되어 설치가 필요합니다.

```bash
npm ci --cache "$PWD/.npm-cache"
npm run start -- --clear
```

5. 맥북과 iPhone을 같은 Wi-Fi에 연결하고 새 QR을 iPhone 카메라로 열어 Expo Go로 실행합니다. 이전 QR은 사용하지 않습니다.

별도 npm 캐시를 사용하므로 기존 사용자 캐시의 권한 오류를 피합니다. sudo나 `npm audit fix --force`는 필요하지 않습니다. 연결이 어려우면 종료 후 `npm run start -- --tunnel --clear`를 사용합니다(tunnel 모듈 설치가 필요할 수 있음). SDK 54와 호환되는 Expo Go가 필요합니다.

## 이번에 복원한 핵심 흐름

### 도시와 날짜

- 기존 웹의 도시 목록을 가져와 한글·영문·별칭 검색과 국가 자동 입력을 복원했습니다. 전 세계 도시 실시간 검색은 아닙니다. 목록 밖 도시는 직접 입력할 수 있습니다.
- 새 여행과 여행 정보 수정에서 월별 달력으로 시작일·종료일을 선택합니다. 월/연도 이동, 날짜 미정, 종료일 순서 검증을 제공합니다.
- **31일 입력·일정 생성 제한을 제거**했습니다. 63일/연도 경계/윤년을 검증했습니다. 긴 여행의 날짜 선택 목록은 가상화합니다.
- 기존 일정이 있는 날짜를 기간에서 제외하면 저장을 막습니다. 기간 연장·빈 날짜 축소·이름/도시 수정은 기존 일정/MUST/후보를 유지합니다.

### Instagram JSON → 게시물 → 장소 후보 → 일정

진입: **챕터 만들기 → 여행 홈의 가져오기**, 또는 **후보 → Instagram JSON 가져오기**.

1. 기기의 파일 선택창에서 Instagram 내보내기 JSON을 선택합니다. ZIP은 먼저 압축을 풀어야 합니다.
2. 컬렉션을 고르고 게시물을 미리 봅니다. 가져올 항목을 선택/해제하고 분류를 수정할 수 있습니다.
3. **가져오기 승인 후에만** 이 여행에 원본 게시물을 저장합니다. 파일 선택 취소·읽기 실패는 여행을 바꾸지 않습니다. 같은 게시물 URL은 중복 제외합니다.
4. 후보 탭의 **게시물**에서 원본 캡션·컬렉션·작성자·원본 링크를 확인합니다. 캡션/@mention에서 추출한 후보 중 실제 장소 이름만 사용자가 선택합니다. 캡션이 없거나 추출이 누락되면 원본을 보고 장소 이름을 직접 추가할 수 있습니다.
5. 선택한 후보를 별도의 **장소**로 저장합니다. 실제 장소 확인이 필요한 상태로 시작하며, 원본 출처를 유지합니다. 같은 이름의 후보는 출처를 합치고, 출처 없는 연결은 만들어내지 않습니다.
6. 장소 상세에서 기존 Google 매칭 서비스의 후보를 요청하거나, 지도에서 위치를 직접 확인하고 반영합니다. **위치 확인 후에만** 날짜와 시간을 직접 골라 일정에 넣습니다.

가져오기·후보 확인·장소 확인은 기존 일정을 재생성하거나 초기화하지 않습니다. 이름/시간/MUST/구간 이동수단/다른 여행을 보호합니다. 일정 배치는 별도 동작이고 같은 날짜의 중복 장소와 같은 시간 충돌을 막습니다. 한 게시물의 출처를 관계없는 장소에 임의로 붙이지 않습니다.

지원하는 대표 JSON 형태: 기존 `label_values`/`dict`/`vec` 컬렉션, Meta `string_list_data`, `string_map_data`, 원본 Instagram URL이 있는 단순 배열 및 컬렉션/게시물 배열. 한국어 인코딩 보정을 포함합니다. Instagram의 모든 시기·언어·내보내기 변형을 보장하지 않으며, 제공받은 saved_collections.json의 중첩 dict 구조를 실제 파일로 검증했습니다. 로그인/스크래핑/자동 동기화/이미지에서 장소 읽기는 구현하지 않았습니다. 후보 추출은 텍스트 규칙 기반이며 AI의 확정 판정이 아닙니다.

파일 전체는 기기에서 읽으며 서버로 전송하지 않습니다. 25MB 이하 파일을 지원하고, 과도한 중첩/규모는 안내 후 중단합니다. 큰 파일은 컬렉션별로 나누어 주세요. 캡션과 원본 링크는 기기에 보관합니다.

### Google 장소 확인: 현재 외부 장애

기존 웹의 `/places-match` 계약에 맞춘 모바일 요청과 응답 선택 UI를 연결했습니다. 버튼을 눌렀을 때 도시·국가·장소 이름만 전송하며, 원본 파일과 캡션은 전송하지 않습니다. API 키를 앱에 추가하지 않습니다.

공개 장소 Ofr. Paris 한 곳을 실제로 조회한 결과, **HTTP 502 / `google_places_error` / `The caller does not have permission`**이 반환됐습니다. 기존 서비스의 Google 접근 권한 문제이며 자동 매칭은 현재 사용 가능한 상태로 확인되지 않았습니다. 운영 서버는 변경하지 않았습니다. 화면에 권한 오류와 지도 직접 확인 경로를 안내합니다. 서버 권한이 복구되면 같은 계약으로 후보를 요청하고 사용자가 선택할 수 있습니다.

## 유지한 모바일 기능

- 이미지 중심 Chapters, 카드 전체 탭, 여행별 상태·홈·일정·후보·기록 탭.
- 탭의 ‘여행 목록’, 상세/수정의 ‘뒤로’와 직접 진입 시 여행 홈 복귀.
- 일정별 위치·설명, 구간별 도보/대중교통/차 저장, 두 장소 간 Google Maps 경로 연결.
- 앱 안 소요 시간 자동 계산은 아직 미연결입니다. 임의 숫자를 넣지 않고 Google Maps에서 확인하도록 표시합니다.
- 기록 작성, 항공·숙소 입력, Buy list, 기존 AI 동선 생성/수정의 모바일 이식은 남아 있습니다. 웹 기능 전체를 이식 완료한 버전은 아닙니다.
- ‘구상 중/준비 중’ 이름 개선은 사용자가 미뤄둔 작업입니다. 판단 기준과 이름은 이번에 바꾸지 않습니다.

## 저장

기존 AsyncStorage 키 `afield:sprint2:trips:v1`을 유지합니다. 원래 후보 ID·일정·MUST를 유지하면서 선택적 국가·원본 게시물·가져온 장소 데이터를 확장합니다. 읽기 실패 시 데이터를 덮어쓰지 않으며, 쓰기 실패는 경고를 표시합니다. 새 ZIP/프로젝트 경로 또는 앱 데이터 초기화에 따라 Expo Go 저장 영역이 달라질 수 있습니다. 다른 기기와 동기화되지 않습니다.

사진은 앱에 포함된 분위기 참고 이미지입니다. 실제 장소 사진이라고 보증하지 않습니다. 출처는 `assets/photos/SOURCES.md`에 있습니다.

## 검증

```bash
npm run typecheck
npm test
npx expo install --check
npx expo export --platform ios --output-dir /tmp/afield-ios-check
```

타입 검사, 테스트 71개, SDK 의존성 호환성 맵 검사와 iOS Hermes 번들 생성으로 검증합니다. 테스트에는 도시/달력 조작, 여러 JSON 형식, 한글 보정, 중복/취소/오류, 출처 보존, 수동 장소 확인 후 배치, 기존 일정/MUST 보존, 앱 재시작 복원을 포함합니다. 실제 iPhone 파일 선택창·iCloud/Files 접근·실제 사용자 내보내기 파일·지도 왕복은 기기 확인이 필요합니다.

SDK 54의 기존 전이 의존성 audit 경고 10개(높음6/중간4)는 남아 있습니다. SDK를 바꾸는 강제 수정은 적용하지 않았습니다.

## 기기 확인 순서

1. 새 여행에서 ‘파리’ 검색 → Paris/France 선택 → 달력으로 날짜 선택. 31일보다 긴 기간도 생성합니다.
2. 챕터를 만든 뒤 홈의 가져오기 또는 기존 Paris → 가고 싶은 곳 → Instagram JSON 가져오기.
3. JSON 선택 → 컬렉션 → 게시물 선택 → 가져오기. 후보 탭의 게시물 목록에 저장됐는지 확인합니다.
4. 게시물 → 원본/캡션 확인 → 장소 후보 선택 → 여행 후보로 추가.
5. 후보의 장소 목록 → 상세 → 지도에서 직접 위치 확인 → 반영 → 날짜/시간 선택 → 일정 추가.
6. 원래 Paris 일정/MUST/다른 여행은 유지되고, 중복 가져오기는 제외되는지 확인합니다.
7. 앱을 닫았다 다시 열어 원본·후보·일정·이동수단 복원을 확인합니다.
8. 파일 선택 취소, 잘못된 JSON, 캡션 없는 게시물, Google 권한 오류에서도 기존 데이터가 유지되는지 확인합니다.

사용한 Expo 파일 선택 방식: https://docs.expo.dev/versions/latest/sdk/document-picker/ (`copyToCacheDirectory: true`).

## 경로와 일정 분류 개선

장소 옆 **경로 찾기**는 Google Maps에서 현재 위치를 출발점으로 사용합니다. 위치를 사용할 수 없으면 Maps에서 출발점을 선택합니다. **이 구간 경로 찾기**는 일정의 두 장소 사이를 연결하고 선택한 이동수단을 사용합니다.

Paris의 Le Marais 산책은 다음에 확인된 Ofr./Temple 또는 Carnavalet/Vosges 권역에 따라 시작점을 추천합니다. 마지막 산책이 Carnavalet 방문 뒤라면 박물관 앞에서 이어갑니다. 다음 장소가 미정이면 보주 광장을 기본 제안하고 그 이유를 표시합니다. 이는 제한된 지역 규칙이며 실시간 거리·소요 시간 기반 최적화가 아닙니다. 기존에 사용자가 정한 위치와 MUST는 바꾸지 않습니다. ‘시작점 바꾸기’에서 수정하거나 저장할 수 있습니다.

일정에 쇼핑·관광·식사·카페/디저트·숙소·이동·기타 태그를 표시합니다. 이름/카테고리로 최초 분류하며 태그를 눌러 수정하면 재실행 후에도 저장됩니다. 후보와 추천 장소에도 분류를 표시합니다.

기기 확인: Paris → 13일 → Carnavalet의 경로 찾기, 이어지는 산책 시작점 확인 → 12일 독립서점 방문을 Ofr.로 지정 → 마레 시작점 갱신 확인 → 태그 수정 후 재실행. 실제 iPhone에서 Maps 왕복은 추가 확인이 필요합니다.

참고: [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), [보주 광장](https://parisjetaime.com/eng/transport/place-des-vosges-p1907), [Temple 정원 주소](https://www.paris.fr/lieux/square-du-temple-elie-wiesel-2425). Temple 시작점은 정원 내부가 아닌 rue de Bretagne 입구 앞입니다.

## 사용 흐름과 조작 영역 개선

- 저장 목록의 탭과 주요 버튼을 ‘가고 싶은 곳’으로 통일합니다. 장소 상세의 ‘가고 싶은 곳에 저장’은 저장만 하고, ‘일정에 추가’에서 날짜/시간을 선택합니다. 원본 게시물에서 추출한 미확인 장소에는 ‘장소 후보’ 표현을 유지합니다.
- 홈의 ‘이번 여행의 발견’ 예시 홍보를 제거합니다. Instagram 가져오기는 저장 목록에 항상 제공하며, 홈에는 저장한 장소가 없을 때만 표시합니다. 예시 목록은 ‘예시 장소 둘러보기’로 표시합니다.
- 장소와 구간의 경로 버튼은 배경/테두리를 갖춘 최소 48 높이 버튼입니다. 태그도 최소 48 높이로 넓힙니다.
- 태그 선택창의 ‘직접 입력’에서 1~20자 분류를 저장할 수 있습니다. 일정별 사용자 태그는 기본 분류와 함께 보관하며 기본 분류를 다시 선택하면 직접 입력한 태그를 해제합니다. 여러 태그를 동시에 추가하는 방식은 아닙니다.
- 미지정 일정에는 실제 장소를 골라야 경로가 생긴다는 설명을 표시합니다. 서점 일정은 ‘서점 고르기’로 안내합니다. 선택 후 일정으로 돌아와 앞 산책의 현재 추천 시작점을 표시합니다. 이미 직접 정한 시작점은 유지합니다.

타입 검사 및 71개 테스트와 iOS 번들 생성으로 검증합니다. 실제 iPhone에서 버튼 크기·키보드·Maps 왕복의 최종 사용성 확인은 별도로 필요합니다.

## 새 챕터부터 확인하는 흐름 (2026-10-26)

- 기존 24개 도시 목록을 GeoNames 34,188개 도시의 오프라인 검색으로 확장했습니다. 시드니/Sydney, 멜버른, 방콕 등 한글/영문 이름과 별칭을 지원하며 인구와 이름 일치로 정렬합니다. 작은 마을이나 모든 별칭을 보장하지 않으며 검색 결과가 없으면 도시/국가를 직접 입력할 수 있습니다. 출처/라이선스: assets/data/SOURCES.md. 도시 입력은 외부로 전송하지 않습니다.
- 생성은 ‘챕터 만들기’ 한 동작입니다. 생성 후 홈이나 ‘가고 싶은 곳’에서 Instagram 가져오기를 선택합니다. 새 여행과 가져오기 화면에 설명용 그림을 포함한 4단계 가이드를 제공합니다. 실제 Instagram UI 스크린샷이 아니며 메뉴 이름의 버전 차이를 안내합니다. 참고: https://help.instagram.com/181231772500920 및 https://about.fb.com/news/2023/10/manage-your-information-across-apps/.
- 여행 목록 카드의 ‘관리’ → 이름/도시/날짜 수정 또는 삭제. 삭제는 확인창을 거쳐 목록에서 숨기며, 목록 아래 ‘삭제한 챕터’에서 복원할 수 있습니다. 일정·MUST·태그·저장한 장소를 보관합니다. 영구 삭제 기능은 아닙니다.
- 본문/입력/필드 제목 글씨를 키우고, 일정 이름(20)을 태그(13)/경로(14)보다 강조합니다. 태그/경로의 시각 영역은 32/36으로 줄이고 hitSlop을 더해 세로 누름 영역 44를 확보합니다. 조작 영역의 실제 기기 사용성 확인은 남아 있습니다.
- JSON 파일 선택 이후 ‘게시물 링크를 찾지 못함’은 실제 사용자 파일에서 재현하고, 중첩 dict의 게시물 컨테이너가 잘못 제외되던 조건을 수정했습니다. 사용자 이름이 포함된 게시물 URL과 post_url/permalink/uri/value 필드를 추가 지원하고, ZIP/HTML/읽기 실패/링크 없는 파일을 구분해 안내합니다. 파일 구조 진단은 최상위 키 이름만 표시하며, 원본을 서버에 전송하지 않습니다. 기존 File 읽기가 실패하면 SDK의 legacy 읽기를 시도합니다. 해당 원본을 직접 파싱해 비어 있지 않은 컬렉션 16개와 게시물 301개를 확인했으며 원본은 저장소에 포함하지 않았습니다. 실제 iPhone 파일 선택 왕복은 추가 확인이 필요합니다.

검증: 타입 검사, 71개 테스트, iOS 번들 생성. 새 챕터 → 시드니 선택 → 달력 → 생성 → 가져오기 가이드 → 실제 저장 항목 JSON 선택부터 확인합니다.

## 원본 JSON 재현 및 가져오기 후 동선 개선

- 2026-10-26: 사용자 제공 saved_collections.json의 게시물 컨테이너가 상위 dict의 원소라는 이유로 URL 말단 노드처럼 건너뛰어지던 문제를 수정했습니다. 말단 URL 중복은 제외하되 실제 게시물 컨테이너는 유지합니다. 혼합된 Unicode/이모지 속 한국어 mojibake도 부분 복원합니다. 개인 원본은 로컬에서만 읽었으며 저장소에 넣지 않았습니다. 동일 구조의 가상 데이터로 회귀 테스트를 추가했습니다.
- 실제 파일 파싱: 비어 있지 않은 컬렉션 16개, 게시물 301개. 같은 내보내기의 saved_posts.json도 로컬에서 1,800개 게시물이 파싱됨을 확인했습니다. 기기 파일 선택창에서의 최종 확인과는 구분합니다.
- 게시물에서 한 장소를 저장하면 바로 위치 확인으로 이동합니다. 장소 이름 직접 입력도 ‘이 이름으로 저장하고 위치 확인’ 한 동작으로 연결합니다. 여러 장소를 저장하면 각각의 위치 확인 버튼을 표시합니다. 기존에 저장한 장소는 원본 게시물에서 다시 열 수 있습니다.
- 위치 확인은 Google Maps 직접 확인을 기본으로 두고, 기존 서버의 이름 검색은 선택 가능한 보조 방법으로 접습니다. Google 권한 장애는 서버를 변경하지 않았으므로 여전히 남아 있습니다.
- 위치를 확인하면 입력 폼을 접고 날짜/시간 선택을 표시합니다. 주소 수정으로 다시 열 수 있습니다. 일정 추가 성공 시 해당 날짜의 일정으로 이동해 추가 안내를 표시합니다. 저장·위치 확인만으로 일정이 생기지 않으며 중복/시간 충돌/MUST 보호는 유지합니다.
- 검증: 타입 검사, 71개 테스트, iOS 번들. 수동 장소 입력 → 저장 → 위치 확인 → 일정 선택까지 컴포넌트/저장소 경계 테스트를 포함합니다.
