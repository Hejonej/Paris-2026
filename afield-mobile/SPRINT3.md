# Sprint 3 — AI 여행 계획 첫 구현

상태: 모바일 구현·자동 검증 완료, 실제 iPhone 사용성 확인 대기. Sprint 3 전체 완료 선언이 아님.

## 진입 및 동선

여행 홈 ‘여행 조건 입력하고 AI로 계획’ 또는 일정 ‘AI로 빈 시간 계획하기’ → 조건 입력 → 조건 저장하고 AI 제안받기 → 날짜별 제안 검토/선택 → 선택한 곳과 고정 일정 적용 → 첫 추가 날짜의 일정으로 이동.

기존 여행의 일정은 모두 보호한다. MUST뿐 아니라 이름, 시각, 주소, 사용자 태그와 기존 구간 이동수단을 유지한다. 이 버전은 ADD 전용이며 기존 AI 일정도 재배치/삭제하지 않는다. 장소 저장·조건 저장·제안 생성만으로 일정은 바뀌지 않는다.

## 입력

- 제안받을 기간: 여행 날짜 안의 부분 기간 선택 가능. 여행 자체의 날짜나 기존 일정은 자르지 않음.
- 하루 시작/종료, 여유롭게/적당히/알차게, 도보/대중교통/차, 장소 사이 여유 분.
- 점심/저녁 각 60분, 휴식 30분 확보. 다른 고정 일정과 겹치거나 항공편으로 활동 시간이 없으면 생략 사유를 표시.
- 여러 숙소의 이름/확인한 주소, 숙박 날짜, 체크인 가능한 시각과 체크아웃 마감. 출발/귀가 위치로 사용. 도착편/출발편에 맞춰 그 범위 안에서 수속 시간을 조정.
- 도착/출발 항공편: 여행지 현지 날짜/시각, 공항, 여유 분. 자정을 넘는 준비 시간도 해당 날짜에 나누어 보호.
- 예약·고정 일정의 이름, 현지 날짜/시각, 체류 시간, 주소 선택.
- 위치가 확인된 저장 장소 선택, ‘꼭 가기’, 예상 체류 분. 새 수동 장소도 확인한 주소로 저장 가능.
- 요청 메모: 취향·짐 보관·특별 요청. 메모는 AI가 참고하는 선호이며 자동으로 검증된 사실이 아님.

## AI 및 검증

운영 설정/키/배포를 변경하지 않고 기존 웹의 `https://travel-ai.luckyjungheywon.workers.dev/plan` 계약을 사용한다. 모바일에 LLM 키를 포함하지 않는다. 생성 버튼을 눌렀을 때 선택 장소 이름/주소, 조건, 기존 일정의 최소 정보만 전송한다. Instagram 파일·캡션·원본 게시물 링크는 전송하지 않는다.

현재 서버는 `suggestions`의 `action`에 문장으로 반환할 수 있다. 명시적 날짜/시각/ID, 엄격한 ADD 파이프 형식, 또는 한 날짜·시각과 선택 장소의 정확한 이름/ID가 명확한 제한된 기존 문장 형식만 읽는다. 모호한 이름, 여러 시각, 알 수 없는 장소, MOVE/DROP 등은 제외한다. 이름 유사도로 새 장소를 추정하지 않는다.

앱이 계산한 빈 시간 구간과 예약 블록을 요청에도 명시하고, 응답을 다시 검증한다. 항공편 가능 시간, 기존 일정/고정 조건, 체류 시간, 이동 여유, 하루 방문 수, 중복, 선택 장소와 MUST를 검사한다. 실제 거리 최적화 결과로 표시하지 않는다.

AI 제안은 기기에 저장되어 재실행 후 검토 가능하다. 일정/장소/조건의 정확한 스냅샷이 달라지면 오래된 제안 적용을 막는다. 선택을 전체 검증한 후 한 번만 적용한다. 같은 제안을 두 번 적용하지 않는다. 이미 추가한 식사/고정 블록은 안정 키로 중복 생성하지 않는다. 새 구간에 선택 이동수단을 넣고 기존 구간 설정은 덮어쓰지 않는다.

## 검증 증거

- 타입 검사, 전체 94개 테스트, iOS Hermes 번들 생성 통과.
- 실제 기존 `/plan` 서비스에 가상 Sydney 여행/숙소/항공편/필수 갤러리를 요청. 문장형 응답과 제약 전달 문제를 재현한 뒤 호환성을 보강함.
- 실제 응답의 2027-02-02 09:00 가상 갤러리 제안을 모바일 검증기가 통과시키고 메모리 상 일정 적용까지 확인. 사용자 실제 여행/게시물을 이 서버 점검에 사용하지 않음.
- 테스트: 자정 항공편, 늦은 체크인/이른 체크아웃, 식당의 식사 슬롯 대체, 고정 일정 충돌, 잘못된 장소/시각/변경 명령 거부, MUST 누락 차단, 스냅샷 변경, 두 번 적용 차단, 기존 항목 보존, 조건/제안 재실행 복원, 수동 장소부터 명시적 적용까지의 네이티브 컴포넌트 흐름, 서비스 실패/취소.

## 현재 한계 / 후속

- 영업시간·휴무·예약 가능 여부·가격·날씨·일몰·접근성·실제 길찾기 소요 시간은 조회하지 않음. AI 반환 필드로 확인 완료를 표시하지 않음.
- 장소 주소는 사용자 확인 또는 기존 장소 확인 결과를 사용. 주소의 지리적 문맥을 AI가 참고하지만 Google Routes 최적화나 정확한 도보량 계산은 연결하지 않음. 이전 Google Places 서비스 권한 오류는 운영 서버를 건드리지 않았으므로 별도 해결이 필요.
- 체류 시간/장소 사이 여유/공항 준비 시간은 계획 가정이다. 항공편은 사용자가 현지 날짜와 시간을 입력하며 자동 시간대 변환·DST 계산/항공편 실시간 상태 조회는 하지 않음.
- 한 번에 최대 100개 장소. 100개보다 많으면 임의로 첫 100개를 고르지 않고 사용자가 대상 장소를 선택. 요청이 커지면 부분 기간/장소 수를 줄이라는 안내.
- 여러 도시 이동, 전체 일정 재최적화, 기존 항목 이동/삭제, 완료 이력 기반 실시간 재계획은 후속. 사용자 고정 조건이 서로 충돌하면 자동으로 옮기지 않고 조건 수정을 요청.
- 실제 기기에서 숙소/항공편 입력, 생성 대기/취소, 검토/적용, 지도 및 앱 재실행 왕복을 확인해야 함.

## 기기 확인

1. 새 챕터를 만들고 날짜 선택. 저장 장소의 위치를 확인하거나 AI 화면에서 수동 장소를 추가.
2. 숙소와 도착/출발 항공편, 식사 시각을 입력하고 조건 저장.
3. AI 제안받기. 이 단계에서 기존 일정이 그대로인지 확인.
4. 제안 시각과 고정 블록, 제외된 장소, 확인 필요 안내를 보고 선택 적용.
5. 첫 추가 날짜가 열리고 식사 자리/장소가 추가되는지, 기존 MUST/태그가 유지되는지 확인.
6. 앱을 다시 열어 조건·미적용 제안·적용 일정이 남는지 확인. 실패/취소 시 기존 일정 보존 확인.
