# Sprint 3 완료 기준 — AI로 여행 계획 만들기

2026-11-18 기준. Sprint 2의 여행 생성·장소 수집·기본 내비게이션 위에, 여행 조건과 저장 장소로 AI 제안을 만들고 선택해서 적용하는 흐름을 완성한다. 새 Sprint 3를 별도로 만드는 것이 아니라 현재 Sprint 3의 마감 범위를 명확히 한다.

## 확인 원칙

- 항상 새 테스트 여행으로 시작한다. 기존 Paris/사용자의 실제 여행을 초기화하거나 수정하는 방식으로 테스트하지 않는다.
- ‘구현됨’, ‘개발 검증됨’, ‘사용자 iPhone 확인됨’을 구분한다. 합성 여행 테스트 성공은 실제 사용자 여행 검증을 대신하지 않는다.
- 체크리스트의 빈 칸은 실패 확정이 아니라 이번 완료 기준으로 아직 확인하지 않은 항목이다.
- 전체 검사 153개·타입 검사·iOS export는 2026-11-18 방문 체크 구현에서 통과했다. 아래의 전체 사용자 여정은 새 테스트 여행에서 최종 확인한다.

## 사용자가 iPhone에서 확인할 체크리스트

### 1. 새 여행과 단계별 입력

- [ ] 새 여행 생성: 도시 검색·달력 날짜 선택 후 여행이 생긴다. 기존 여행 내용은 유지된다.
- [ ] AI 계획에서 화면이 숙소·항공편·예약 → 장소 모으기 → 하루 속도·식사·이동·추가 요청 순서로 나뉜다.
- [ ] 항공편을 입력하지 않거나 입력 중으로 남겨도 저장하고 다음으로 넘어간다. 뒤로 가거나 다시 열어도 저장한 내용을 이어간다.

### 2. 숙소·항공편·고정 예약

- [ ] 숙소 이름 검색 → 입력창 바로 아래 결과 → 행 선택으로 이름·주소가 채워진다. 다른 입력창을 가리지 않고 결과를 누를 수 있다.
- [ ] 출발·도착 공항을 한글·영문·코드로 찾아 선택한다. 선택 후 이름·코드가 간결하게 보인다.
- [ ] ‘이 항공편 사용’으로 확정한 항공편과 고정 예약을 반영하되, 입력 중 항공편은 실제 제약으로 사용하지 않는다.
- [ ] 키보드가 올라와도 입력/검색 결과/저장 버튼을 스크롤해서 조작할 수 있다.

### 3. 장소 모으기

- [ ] Instagram JSON 가져오기 → 게시물에서 장소 고르기 → 주소 확인 → 저장한 장소 목록으로 복귀한다.
- [ ] 수동으로도 장소를 추가한다. 저장한 장소·원본 게시물·주소 확인·일정 배치 상태가 구분된다.
- [ ] ‘아직 미정 · AI가 배치’는 사용자에게 날짜/시간을 요구하지 않는다. 장소를 저장한 것만으로 일정에 들어가지 않는다.

### 4. AI 생성과 동선

- [ ] 저장한 장소 3–5곳을 선택하고, 도보+대중교통을 선택한 뒤 제안받는다.
- [ ] 숙소 출발/귀가, 항공편, 고정 예약, 하루의 속도와 식사 희망 시각이 제안에 반영된다. 일반 장소에 고정 체류시간을 강요하지 않는다.
- [ ] 확인된 도보·대중교통 시간이 모두 있으면 빠른 쪽을 사용한다. 출발지·도착지·수단을 보여주며 임의의 긴 도보로 대체하지 않는다.
- [ ] 미확인 교통시간을 실제 시간으로 표시하지 않는다. 미배치 장소에는 사용자가 이해할 수 있는 구체적 이유와 다음 행동이 나온다. 이유 없는 0곳 결과를 완료로 간주하지 않는다.

### 5. 검토·선택 적용·보호

- [ ] 제안을 받기만 했을 때는 기존 일정이 바뀌지 않는다. 추천 이유를 열어도 선택 상태가 바뀌지 않는다.
- [ ] 일부 장소만 선택해서 적용하면 선택한 장소만 정확히 한 번 들어간다. 다시 적용해도 중복되지 않는다.
- [ ] 기존 사용자 일정·MUST·예약·태그·기록·완료 상태는 보존된다. 조건/일정 변경 뒤 오래된 제안은 적용을 막는다.
- [ ] 취소·실패·재시도에서 기존 장소와 일정이 사라지지 않는다. 완료되지 않은 결과를 성공처럼 표시하지 않는다.

### 6. 실제 여행 중 사용

- [ ] 적용한 날짜의 일정이 열리고, 경로 찾기 → Google Maps → 앱 복귀가 가능하다.
- [ ] 수동 편집 → 검토 → 저장 → 직후 되돌리기가 동작하고 보호된 일정은 이동하지 않는다.
- [ ] 지난 날짜의 장소를 방문 체크·취소하고 다시 열면 유지된다. 하루 정리에서 미체크 장소가 자동 이동/삭제되지 않는다.
- [ ] 앱 재실행 후 여행 조건·저장 장소·미적용 제안·적용 일정·방문 체크가 유지된다.

## 개발자가 마감 전에 확인할 항목

- [ ] 위 전체 흐름을 같은 새 테스트 여행으로 끝까지 검증하고, 사용한 조건·결과·미확인 사항을 기록한다.
- [ ] AI 0곳/부분 성공/교통시간 조회 실패/생성 취소/오래된 초안/중복 적용의 회귀 검증을 통과한다.
- [ ] DESIGN_SYSTEM.md의 남은 공통 컴포넌트 정리와 320/390pt·큰 글씨·키보드·뒤로가기 검증을 마친다. iPhone과 Android 결과는 구분한다.
- [ ] 최종 변경 기준 타입 검사·관련 자동 검사·iOS export를 통과하고, main/운영 Cloudflare/운영 여행 데이터가 변경되지 않았음을 확인한다.

## 현재 열려 있는 핵심 항목

- 일본 대중교통의 실제 시간 자동 조회는 미완료다. 현재 위치 기반 제안과 ‘시간 확인 필요’ 임시 배치를 지원하지만, 실제 대중교통 시간을 확인한 것으로 간주하지 않는다. 핵심 동선 기능의 남은 이슈로 별도 추적한다.
- 실제 항공편 자동 조회·실시간 운항 상태는 미연결이다. 현재는 공항 검색과 예약 정보 직접 입력이며, 자동 항공편 조회를 Sprint 3 완료 기능으로 표기하지 않는다.
- 실제 사용자 여행의 전체 생성→검토→적용 검증과 물리 기기 큰 글씨/키보드/스와이프 확인이 남아 있다.

## Sprint 3 범위 밖

2026-11-18 확장으로 여러 미방문 장소의 Google/AI 이동 제안·선택 적용·이동 이력·직후 되돌리기를 구현했다. 기존 ADD 초안과 분리하며 미리보기에서 나가면 적용 없이 취소한다. 마지막 날 오늘 남은 시간 배치, 별도의 보관/제외 상태와 이동 미리보기 재실행 보존은 후속이다. 자동 사진 수집/공유·실시간 항공편 조회·다중 도시 전체 재최적화·출시용 서버 전환도 이번 마감에 몰래 포함하지 않는다.

## 완료 선언

핵심 전체 여정과 데이터 보호가 검증되고 사용자 iPhone 확인이 끝나야 완료로 표시한다. 미확인 교통·항공편 기능은 실제 지원 범위를 명시하며, 남은 기능을 UI 설명만 고친 채 구현 완료로 처리하지 않는다. 현재 상태는 **완료 기준 정리, 최종 검증 진행 전**이다.
