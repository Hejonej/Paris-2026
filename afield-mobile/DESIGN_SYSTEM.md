# Afield Mobile · Contemporary Culture × Modern Minimal × Spatial Utility

2026-11-14 사용자 지침을 디자인의 최상위 기준으로 적용한다. Vintage Travel Diary, 여행 매거진, 크림/올리브/세피아/세리프 방향은 폐기한다.

## 기반

- iOS/Android의 기본 시스템 산세리프. 별도 폰트 다운로드 없이 한국어와 라틴 문자를 일관되게 표시한다. Pretendard/Inter 도입은 추후 실제 바이너리·라이선스 확인 후 선택 가능.
- 배경 #FAFAFA, 표면 #FFFFFF, 본문 #161616, 보조 #696969, 구분선 #E5E5E5. 기능 강조 #245BDB는 링크·선택·경로에 제한한다. 주요 CTA는 검정.
- 기본 간격 4/8/12/16/24/32pt. 미디어 모서리 8pt, 조작 10pt, 바텀시트 24pt. 모든 요소를 동일한 둥근 카드에 넣지 않는다.
- 사진은 원본 컬러. 세피아나 장식용 색상 오버레이를 사용하지 않는다. 사용자 선택 대표 사진을 유지한다.
- 터치 목표 최소 44pt. 시각적인 태그는 작게 유지하되 독립된 터치 영역을 갖는다. 큰 글씨 설정에서 제목·메타데이터가 겹치지 않도록 줄바꿈과 flex를 허용한다.

## 1차 구현: 핵심 화면 3개

### Chapters
96×120pt 사진 + 여행 메타데이터의 한 행. 도시/상태, 이름, 기간, 일정·저장 수 순서로 읽힌다. 행 전체가 진입 버튼이며 편집 모드에서는 체크 선택으로 전환한다. 정보는 선으로 구분하고 큰 카드/여행 감성 카피/일정 미리보기는 반복하지 않는다. 편집·복수 삭제·복원·대표 사진 기능 보존.

### 여행 홈
여행 이름과 작은 대표 사진 → 일정/저장 수 → 현재 상태의 다음 행동 → 날짜별 일정 미리보기 → 조건/AI 진입 순서. 날짜 미정/준비/여행 중/다녀온 여행에서 행동을 달리한다. 오늘이 여행 기간 안이면 빈 날이라도 오늘을 우선한다. 동일한 크기의 카드 여러 개로 기능을 나열하지 않는다.

### 일정
간결한 제목/AI 계획 도구 → 스크롤 중 유지되는 날짜 레일 → 날짜 요약 → 시간과 장소를 연결하는 타임라인. 장소명과 태그 우선, 설명은 2줄, 시작점 추천 근거는 필요할 때 펼친다. 장소의 현재 위치 경로와 장소 사이의 구간 경로를 구분한다. 이동수단·MUST·사용자 태그·추천 시작점은 보존한다. 실제 이동시간을 조회하지 않은 경우 숫자를 만들지 않는다.

## 내비게이션과 상호작용

- 여행 내부 4탭 유지: 홈/일정/가고 싶은 곳/기록. 화면 진입은 Stack, 상세는 기존 native modal을 사용하며 뒤로/닫기와 스와이프 복귀를 플랫폼에 맡긴다. 하단 안전 영역을 포함해 탭 높이를 계산한다.
- Chapters의 편집은 선택 → 하단 관리 작업 → 삭제 확인, 복원 유지. 사용자 데이터 삭제를 스와이프 즉시 실행으로 대체하지 않는다.
- 일정 날짜는 고정 레일, 태그/장소 선택은 단발성 시트가 적합하다. 현재 태그 편집 Modal은 기능 보존하고 후속 단계에서 안전 영역/스크롤/닫기 동작이 있는 바텀시트 primitive로 통합한다.
- 저장/적용/삭제 같은 확정 행동과 탐색/설정 같은 보조 행동을 시각적으로 구분한다. 실패·빈 결과·진행 중 상태는 별도이며 단순 공백으로 표현하지 않는다.

## 다음 확장 순서와 정보 위계

1. 가고 싶은 곳: Instagram 원본/추출 장소/주소 확인/일정 배치 여부를 서로 다른 상태로 표시. 게시물은 출처, 장소는 계획 대상이다.
2. AI 추천/계획: 현재 여행 조건, 제안 이유, 미배치 이유를 연결하고 선택한 제안만 수락. 자동 적용/기존 일정 덮어쓰기 금지.
3. 장소 상세: 사진·장소명·주소 우선. 후보 저장과 일정 추가는 별도 행동. 미정은 AI가 방문 일시를 정한다는 뜻.
4. 기록: 방문 장소·사진·짧은 메모의 흐름. 기사식 장문 카드로 바꾸지 않는다.

1차에서는 이 후속 화면의 기능/레이아웃을 전면 재작성하지 않는다. 폐기된 팔레트만 뉴트럴로 정리했다. 사진 보관/Instagram/AI 파서/여행 저장 구조와 키는 변경하지 않는다.

## 검증과 한계

- 기존 기능 및 상태별 홈 이동 회귀 테스트, 타입 검사, iOS Hermes export.
- 임시 react-native-web 렌더링으로 390pt/320pt 폭에서 세 핵심 화면과 스크롤/줄바꿈을 검토한다. QA 도구는 앱 package.json/잠금 파일에 추가하지 않는다.
- 웹 렌더링은 iOS/Android 네이티브 QA를 대신하지 않는다. 실제 iPhone의 안전 영역, 큰 글씨, 키보드, 스와이프는 기기에서 최종 확인한다.
