# AI 계획 입력 순서 제안

2026-11-14 사용자 의견에 대한 UX 제안. 이번 변경에서 단계형 wizard 전체를 구현하지는 않는다. 현재 조건 폼/저장/제안 기능은 유지하며, 다음 구조로 나누는 것을 제안한다.

1. 여행의 고정 조건: 숙소, 항공편, 예약/고정 일정. ‘저장하고 다음’으로 보관하고, 미정 항목은 ‘나중에 입력’으로 건너뛸 수 있다. 항공권 파일이나 예약 결제를 요구하는 단계가 아니라 필요한 현지 시간·위치를 받는 단계다.
2. 가고 싶은 장소: Instagram 원본 가져오기 → 장소 선택 → 주소 확인, 또는 직접 장소 추가. 원본 게시물과 계획할 장소를 구분한다. 이미 저장한 장소가 있으면 다시 가져오게 하지 않고 이어서 사용한다. 이 단계에서 방문 일시를 필수로 받지 않는다.
3. 이번 여행의 방식: 여행 속도, 하루 시작/마무리, 식사·휴식 선호, 이동수단 복수 선택. 기본값으로 바로 진행할 수 있고 세부 옵션은 펼친다. 식사 선호와 고정 예약은 다른 강도로 취급한다.
4. 취향과 추가 요청: 짧은 주관식 한 칸. ‘많이 걷기 어려움’, ‘마지막 날 짐 보관’ 등의 예시를 제공하지만 선택 입력이다. AI가 참고할 텍스트이지 실제 이동·영업·접근성 검증 자료가 아님을 구분한다.
5. 생성 전 요약: 입력된 고정 조건, 주소 확인된 미배치 장소 수, 여행 방식. 빠진 필수 정보만 알려주고 사용자가 생성한다.
6. 제안 검토: 날짜별 제안과 이유, 제외된 장소의 구체적 이유, 바뀌지 않는 기존 일정. 선택한 제안만 명시적으로 적용한다.

모든 단계는 뒤로 가도 입력을 유지한다. 외부 지도/파일 선택 후 돌아오는 위치를 보존하고, 단계마다 별도 저장 여부를 알린다. 첫 단계에서 숙소·항공편이 없다는 이유만으로 계획 전체를 막지 않는다. 날짜·장소 주소처럼 실제 생성에 필요한 조건은 생성 직전에 검증한다. 재시도는 입력 과정을 다시 강요하지 않는다.
